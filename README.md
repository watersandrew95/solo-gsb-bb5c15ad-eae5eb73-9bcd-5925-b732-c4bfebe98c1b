# 管网漏点隔离规划台

录入无向管段、进水点、漏点、必保供水点和绑定管段的阀门（最多 14 个，关闭代价为正整数），
系统自动求出**使全部漏点与所有进水点断开、且每个必保供水点仍连通至少一个进水点**的
**最低总代价关阀组合**；总代价相同时取“阀门编号升序列表”字典序最小者；无解时给出具体原因。

- 后端：Python + FastAPI + SQLite（枚举全部 2ⁿ 种关阀组合，保证最优）
- 前端：原生 JavaScript 单页（输入、关阀清单、管网状态图、各节点供水状态表）

## 一键启动（单条命令）

```bash
docker compose up --build
```

启动时自动安装依赖并初始化数据库（建表；空库自动写入一个示例方案，打开页面即可直接求解）。

## 地址与端口

| 内容 | 地址 |
|---|---|
| 操作页面 | http://localhost:8000/ |
| API 文档（Swagger） | http://localhost:8000/docs |
| 健康检查 | http://localhost:8000/api/health |

## 配置（均可选）

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8000` | 容器内监听端口；同时作为宿主机映射端口（`PORT=9000 docker compose up --build` 即可改端口） |
| `DATA_DIR` | `/app/data` | SQLite 数据目录（Compose 已挂载命名卷 `pwnet-data` 持久化） |

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/scenario` | 读取当前方案 |
| `PUT` | `/api/scenario` | 整体保存方案（服务端校验：阀门 ≤14、编号唯一、代价为正整数、绑定管段须存在） |
| `POST` | `/api/scenario/demo` | 重置为内置示例方案 |
| `POST` | `/api/solve` | 求解最优关阀组合并保存结果 |
| `GET` | `/api/result` | 读取最近一次求解结果 |

## 页面输入格式

- **管段**：每行一条无向管段 → `端点A 端点B`（如 `S1 A`）
- **进水点 / 漏点 / 必保供水点**：空格、逗号或顿号分隔（如 `S1 S2`）
- **阀门**：每行一个 → `编号 端点A 端点B 关闭代价`（如 `3 B L1 2`），最多 14 个

求解结果页展示：最低总代价与关阀清单、被切断的管段、管网状态图（环形布局，
红色虚线为被切断管段）、以及每个节点隔离后的供水状态（供水正常 / 停水 / 漏点已隔离）。

## 无解时的原因说明

系统会明确给出不可行的原因，包括：漏点与进水点/必保点角色重叠、必保点与所有进水点
本身不连通、漏点与进水点间存在无阀门通路（关光阀门也隔不断）、以及“隔离漏点”与
“保住必保点供水”两类约束冲突（并指出受影响的必保点）。

## 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 项目结构

```
├── Dockerfile             # 一键构建：安装依赖，启动时自动初始化数据库
├── docker-compose.yml     # 单条命令启动，含端口映射与数据卷
├── requirements.txt
└── app/
    ├── main.py            # FastAPI 入口：API 路由 + 输入校验 + 静态页面
    ├── solver.py          # 求解核心：枚举 2^n 关阀组合 + 无解诊断
    ├── database.py        # SQLite 建表、方案/结果存取、示例方案
    └── static/            # 原生 JS 单页（index.html / app.js / style.css）
```
